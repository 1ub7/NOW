# Git Flow
## 1. 개념
**Git Flow란?**     
Git을 사용할 때 브랜치를 역할별로 나누어 체계적으로 개발하기 위한 브랜치 전략
## 2. 주요 브랜치 종류
**main** : 사용자에게 실제로 배포되는 가장 안정적인 코드만 존재하는 브랜치      
- 테스트가 끝난 코드만 존재
- 오류가 최소화되어야 함

**develop** : 개발자들이 만든 기능들을 모아서 관리하는 브랜치   
- feature 브랜치들의 집합 장소
- 개발 중인 최신 코드

**feat(ure)** : 새로운 기능을 개발할 때 사용하는 브랜치     
- 기능별 작업 분리를 시켜야함
- 충돌을 감소시킴

**release** : 배포 전에 최종 점검을 위한 브랜치     
- 성능 점검 및 버전 관리함

**hotfix** : 운영 중인 서비스에서 긴급 문제가 발생했을 때 사용하는 브랜치   


## 2-1. 브랜치 종류 표
| 브랜치 | 역할 |
| ----- | ----- |
| main | 실제 배포되는 안정 버전 |
| develop | 개발 내용을 통합하는 브랜치 |
| feature/* | 기능 개발 브랜치 |
| release/* | 배포 준비 브랜치 |
| hotfix/* | 긴급 수정 브랜치 |

## 3. 작업 흐름
-develop 브랜치에서 feature 브랜치 생성     
-feature 브랜치에서 기능 구현 작업 진행     
-feature -> develop PR 생성     
-기능 개발 끝나면 develop 브랜치로 merge    
-Release 브랜치 생성    
-Release -> main PR 생성        
-Release 브랜치를 main 브랜치에 Merge   
-Release 내용을 develop에도 반영
